# 收入合同模型简明说明

## 1. 核心业务链路

```text
客户/项目
  ↓
收入合同 → 合同版本 → 合同项 → 计费规则
  ↓
应收账单 → 应收明细
  ↓             ↓
发票明细 ← 发票映射 → 回款分配 ← 回款
```

收入合同模块用于管理从“签订合同”到“形成应收、开票、回款”的完整经营链路。

## 2. 核心模型

| 模型 | 中文名称 | 主要作用 |
| --- | --- | --- |
| `RevenueCustomer` | 客户 | 保存收入客户主数据 |
| `RevenueProject` | 项目 | 保存客户下的业务项目 |
| `RevenueContract` | 收入合同 | 保存合同主体、期间、金额和状态 |
| `RevenueOrder` | 订单/开工单 | 记录框架合同下的具体订单 |
| `RevenueContractVersion` | 合同版本 | 保存原合同、补充协议、调价等版本 |
| `RevenueContractLine` | 合同项 | 保存具体收费项目、单价和数量 |
| `RevenueBillingRule` | 计费规则 | 定义何时、如何形成应收 |
| `RevenueReceivableBill` | 应收账单 | 按合同和账期归集应收 |
| `RevenueReceivableLine` | 应收明细 | 可追溯到具体合同项和计费规则 |
| `RevenueInvoice` | 发票 | 保存发票主信息 |
| `RevenueInvoiceLine` | 发票明细 | 保存发票中的具体收费行 |
| `RevenueInvoiceMapping` | 发票映射 | 记录发票明细覆盖了哪些应收 |
| `RevenueReceipt` | 回款 | 保存客户实际到账记录 |
| `RevenueReceiptAllocation` | 回款分配 | 记录回款核销了哪些应收 |

## 3. 辅助模型

| 模型 | 作用 |
| --- | --- |
| `RevenueContractProject` | 建立合同与项目的多对多关系 |
| `RevenueBillingSegment` | 保存某段计费期间的计算结果和规则快照 |
| `RevenueTriggerRecord` | 保存开通、验收、交付等实际业务事件 |
| `RevenueAdjustmentRecord` | 解释折扣、扣款、退款等金额调整 |
| `RevenueReceivablePlan` | 兼容历史应收计划 |
| `RevenueReceivablePlanVersion` | 保存应收计划的版本变化 |
| `RevenueSyncLog` | 保存外部系统同步日志 |

应收计划相关模型主要用于兼容存量数据。当前主流程由计费规则直接生成应收。

## 4. 计费规则

计费规则分为三类：

| 类型 | 说明 |
| --- | --- |
| `recurring` | 周期性计费，例如月租、季租、年租 |
| `milestone` | 阶段性计费，例如验收后收费 |
| `one_time` | 一次性计费，例如安装费 |

周期性规则按账期生成应收。

阶段性和一次性规则需要先产生已确认的业务触发记录，再按照以下方式确定应收日期：

```text
应收形成日 = 实际触发日 + 触发偏移天数
```

## 5. 金额关系

### 应收

```text
应收净额 = 原始金额 + 修正金额
```

### 开票

发票和应收通过 `RevenueInvoiceMapping` 建立金额关系：

```text
应收明细的有效映射合计 ≤ 应收明细净额
发票明细的有效映射合计 ≤ 发票明细金额
```

### 回款

回款通过 `RevenueReceiptAllocation` 分配到应收明细：

```text
已分配金额 = 有效回款分配合计
待分配余额 = 回款金额 - 已分配金额
```

回款分配不能超过：

- 回款到账金额；
- 应收明细净额；
- 所关联的发票映射金额。

## 6. 主要数据关系

- 一个客户可以有多个项目和多个合同。
- 一个合同可以关联多个项目、版本、订单和合同项。
- 一个合同项可以有多个计费规则。
- 一个应收账单可以有多条应收明细。
- 应收明细与发票明细是多对多金额映射关系。
- 一笔回款可以分配给多条应收明细。
- 一条应收明细也可以由多笔回款核销。

## 7. 关键注意事项

1. 新数据应优先使用结构化订单字段 `revenue_order`，`order_id` 只用于兼容历史数据。
2. `RevenueReceivableLine.idempotent_key` 用于防止重复生成应收。
3. 账单上的已开票、已回款金额属于汇总字段，准确核对时应以有效发票映射和有效回款分配为准。
4. 已进入应收、开票或回款链路的数据应优先作废或解绑，不建议直接删除。
5. Django 直接调用 `save()` 或 ORM `create()` 不会自动执行大多数模型的 `clean()`；导入脚本应主动调用 `full_clean()`。

## 8. 一句话理解

收入合同模型以“合同项和计费规则”为计费基础，以“应收明细”为业务核算中心，通过发票映射和回款分配完成从合同到收款的全链路追溯。
